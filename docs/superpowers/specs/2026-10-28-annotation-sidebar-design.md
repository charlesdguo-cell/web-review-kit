# 页面内容批注：飞书实操调研与侧栏方案

日期：2026-10-28。状态：已完成本地实现与验证；用户在菜单修复后确认“验收通过”。随后经授权，在独立 demo 完成真实 Codex 问答、同线程追问及修改／构建／检查／待验收回写验证，现等待用户体验确认后再发布。原模拟演示和记录保留。上一轮“常驻总览列表＋单条详情”已回退。详见[交互验证记录](../../validation-2026-10-28-annotation-sidebar.md)与[真实 Codex 验证记录](../../validation-2026-10-28-real-codex-demo.md)。

## 目标

正常阅读时划词批注；右侧展开批注，每条与原文关联，能遍历当前页面的所有批注。评论框保持简洁。输入区底部提供默认开启的“Agent响应”：问题回答，明确修改要求执行并回复结果。内容批注继续独立于原有评论模式、评论数据和批次。

## 调研依据与实际操作

## 方案选择

采用**与原文对齐的侧栏卡片**。这个方向直接符合用户已明确的诉求。

- 常驻紧凑总览＋独占详情：已被用户否定，不沿用。
- 单个悬浮评论框：轻量，但不能在阅读中发现全部批注，不满足本轮目标。
- 原文旁侧栏卡片：保留上下文与多条评论关系；需要处理正文避让、卡片碰撞和导航。本方案采用这一方向。

## 交互方案

### 1. 展开、发现与定位

- “内容批注”入口始终可用，无需进入评论模式，显示当前页面的批注数量；不混入其他页面。
- 桌面展开后使用右侧连续边栏，不再使用四周留空、重阴影的大浮窗。建议宽度 320px，作为我们针对 Agent 回复长度的取值，不声称是飞书原尺寸。
- 顶栏仅保留“批注 · N”、上一条/下一条、更多、收起。默认看未解决，更多菜单可切换“全部 / 已解决”；标题清楚显示当前范围及总数。
- 卡片按原文位置排列，随对应正文滚动。打开侧栏不主动跳离当前阅读位置。
- 当前视口没有批注时，在侧栏留一个轻量“跳到最近批注”入口；没有后续批注时可回到首条。上一条/下一条按文档顺序遍历，边界禁用。这样能找全批注，不需要额外总览列表。
- 点击原文下划线或卡片引用，双方同步激活。目标已经可见时保持正文位置；目标不可见时才滚到可读区域。点击卡片内按钮、选择文字不触发额外跳转。
- 同一段有多条批注时保留独立卡片和顺序；点击原文激活最近使用的一条，再用同处数量提示或上一条/下一条访问其余条，不合并不同会话。

### 2. 卡片避让与长回复

- 无激活卡片时，以原文纵向位置为目标，按文档顺序排列，碰撞时向下让开。
- 有激活卡片时，优先让它对齐原文；前面的卡片向上、后面的卡片向下避让，始终保持顺序和最小间距。
- 同时只展开一个回复输入框，切换卡片保留各自草稿。
- 长 Agent 回复默认显示可读的前几行和“展开回复”，在原卡片内展开；不进入另一张详情页。展开后邻近卡片让位，不自动滚走正文。
- 正常阅读只使用正文主滚动，不给每张引用、正文、回复再加独立滚动条。输入框增长到合理上限后才在框内滚动。展开超长线程可通过正文滚动继续读完，回复入口保留在该线程末尾。
- Agent 更新只更新自己的消息与卡片高度，不抢焦点、不切换卡片、不强制自动滚动。用户主动进入线程末尾时才跟随新增内容。
- “…”菜单在定时同步、回复更新及状态更新时保留展开状态和焦点。再次点击入口、选择菜单项、点击菜单外或按 Esc 才主动收起；Esc 优先关闭菜单，保留侧栏。菜单内操作不触发卡片切换或正文滚动。

### 3. 新增与回复

- 划词后出现小“批注”按钮；点击后在原文旁创建草稿卡，保留原文浅色高亮。
- 草稿卡只保留单行引用、输入框、图片图标、发送，以及底行“Agent响应”开关。按用户后续调整，右上角 × 用于显式放弃草稿，不再单独显示“放弃草稿”一栏；收起整个侧栏仍保留非空草稿。
- 已有卡片按“你 → Agent → 你”的顺序就地讨论，首条用户评论只显示一次。引用默认一行截断，悬停/展开可看完整引用。
- Cmd/Ctrl+Enter 发送；IME 确认不提交。Esc 退出当前输入/收起侧栏时保留草稿，恢复合理焦点。点击页面正文只取消卡片激活，不自动关闭整个侧栏。

### 4. Agent 响应

- 开关放在**当前卡片输入区的最底行**，默认开启，随该草稿保存；作用于这次发送，不作为整个项目的任务总开关。
- 开：保存本次消息后，交给这条批注的同一 Agent 会话。关：保存为普通批注/回复，不派发 Agent；不禁止发送。
- 首条与追问采用相同规则。现有追问接口必定触发 Agent，因此实现时需要补充“仅保存回复”的服务端语义，不能只改开关外观。
- 重新开启不会自动补发历史消息；后续明确发送给 Agent 时可携带该线程内已保存的上下文。关闭开关不会停止已运行任务，停止仍是单独动作。
- 发送待确认时锁定本次选择和消息内容；重试确认必须沿用同一请求，不能重复保存/执行。
- 排队显示“等待 Agent”；运行显示一行“Agent 回复中…”及必要的停止入口；完成后直接留下回复，不额外放“已保存 / 已完成 / 完整回复”区块。执行修改且已验证后，才显示小型“待验收”标识，解决由用户操作。
- 失败时才出现简短原因和“重试”；详细执行信息收进按需展开项。共享、离线和桥接不可用时开关禁用并给出短原因，仍可保存，不延后自动派发。

## 样式减法

| 现在 | 改为 |
| --- | --- |
| “页面内容·独立批注”＋“批注 #N”双标题 | 侧栏一行“批注 · N” |
| 常驻“全部批注 / 刷新 / 导出”工具行 | 正常自动同步；筛选、导出放更多菜单，连接异常才显示重试同步 |
| 大块引用＋单独原评论＋消息流中重复首条 | 一行浅色引用；首条用户消息仅保留一次 |
| “定位原文 / 查看截图 / 标为解决 / 状态”整行 | 点击引用定位；解决用小图标；截图放更多菜单 |
| 独立进度框、结果框、能力说明、快捷键提示 | 只在进行中/异常时显示必要的一行；快捷键放提示 |
| 深色大浮窗、明显阴影、多层边框、聊天气泡 | 页面相配的浅色/深色边栏，细分隔、平铺消息；仅激活卡片适度强调 |

建议正文 13–14px、行高约 1.6，卡内留白 12–16px；原有评论模式样式不改。截图与附件继续完整保存，视觉上减少入口而非删除证据。

## 实现边界与确实需要处理的难点

没有原理上的障碍。已有独立数据、持久对话、Range 与前后文校验可以复用。主要工作是：卡片布局/事件与草稿维护、正文避让、仅保存回复的契约。

工具接入任意静态 HTML，不能假定所有正文都像飞书编辑器一样有可控容器。旧方案的“正文不重排”需在本方案中明确修订：支持阅读布局的页面打开侧栏时预留宽度。

- 普通文档布局：保留正文阅读锚点后，为右侧预留 320px，再重新计算文字 Range。关闭恢复原尺寸及阅读位置，不缩放整页。
- 固定宽度、全屏画布或内层滚动页面：通过显式布局/滚动容器配置接入，避免对整个 body 加 transform 或任意包裹业务 DOM。无法安全并排时使用覆盖式抽屉，并保留原文定位；不能宣称所有任意页面都已实现飞书式正文避让。
- 本轮首先验收普通文档型静态页面，包括当前合成演示；复杂页面适配不隐含消费者升级或重构。
- 窄屏使用抽屉展示同一组卡片及当前引用，“返回原文”收起抽屉并定位；此处是我们的适配方案，不是飞书移动端实测结论。
- 锚点无法唯一恢复时不猜位置。将该卡保留在可访问的“原文已变化”区域，提供原引用和截图；不会丢弃或错误绑定其他正文。

## 后续验收场景

1. 三条远距离批注，展开/滚动/上下导航均能找到，点击双方关联。
2. 两条相邻和同段重叠批注，切换当前项、长回复展开后不覆盖、不乱序。
3. 视口没有批注但本页有记录时，数量与跳转入口仍可用；异页记录不混入。
4. 多卡草稿、输入法、轮询、流式更新、刷新后焦点和文字不丢。
5. 开关默认开；首条/追问关闭均仅保存；重新打开不补派，停止与重试语义明确。
6. 初始消息和最终 Agent 回复各只出现一次；截图/附件仍可访问和导出。
7. 普通文档的桌面避让、窄屏抽屉、键盘和触摸；复杂布局降级清楚可用。
8. 已解决与锚点变化记录可找回；旧评论、共享、离线、队列和幂等契约保留。
