# 批注修改后的页面刷新与持续定位

用户反馈：真实 demo 修改后没有自动刷新，原批注似乎消失。本次是在已验收侧栏及真实 demo 范围内修复体验，不发布、不升级其他消费者。

只读复现：三条批注仍在服务中。旧文字改写后精确 Range 失败，原文编号不再显示，卡片被排到屏幕下方；刷新会重置侧栏展开状态。

## 处理方式

- 保留严格的文字 Range 匹配；失败时仅使用仍可可靠确认的原容器作段落定位，显示轻量的段落标记和“原文已变化”提示。原引用、锚点、截图和记录不回写、不覆盖。
- 不能可靠确认原容器时，保留稳定位置的卡片和可见导航入口；不把旧批注绑定到碰巧占据相同位置的新段落。
- 当前页面的批注明确修改完成（新 `changed` 版本且会话 `completed`），并且构建不同于已加载页面时，自动刷新。普通问答、历史完成记录、其他页面更新、共享/离线/禁用 Agent 不触发。
- 按项目与页面保存侧栏展开、当前批注、筛选、展开回复和阅读/抽屉滚动位置，自动或手动刷新后恢复一次。原有草稿和发送请求存储仍是唯一来源，不重放任何消息。
- 有未发送批注/回复、待确认发送、输入法组合输入、正文表单输入、旧评论编辑或发送操作时暂缓自动刷新，提供简洁的“内容已更新”提示。存储失败也不强行刷新。

## 取舍

直接替换页面 DOM 会破坏消费者自己的脚本状态，故使用完整刷新并恢复批注视图。仅提示手动刷新不能满足本次反馈。把旧引用改成新文字会改写评审证据，故使用只读的段落定位回退。

段落回退只代表原容器，不声称新文字仍是原引用。整个原容器被删除时只能保留讨论及证据，不猜测新的文字关联。

## 验证

合成项目覆盖原句改写、容器删除、全部失配后滚动稳定、真实页面 reload、当前批注与阅读位置恢复、草稿/IME/待确认保护、无刷新循环、跨页面和 shared/offline 排除。运行独立全套及相关浏览器回归；真实 demo 只读核对、备份和更新当前工具资产，不启动或改变真实任务。
